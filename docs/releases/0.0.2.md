Linux/macOS 编译器使用上游 `b09075b6a93e6afe10645181e3aeff041ea37f87` 加完整补丁 `cf69ac0418f940e1ccc950ecff72d81e29a017847172747dc2cf3e31d26fabb3`。Linux 在 Debian 11 容器中构建，检查全部 ELF 架构、未解析依赖和 RPATH，最高需求 GLIBC 2.29 / GLIBCXX 3.4.21。macOS 两个架构的最低部署目标均为 11.0，Mach-O 架构及系统动态库检查通过。Windows plain-C 仍为未修改的上游编译器，其 C++ 路径使用独立 WSL 工具链。

stc-cli 0.1.0 的源提交为 `94d0f2d3133fee2340c768ffdf5dd11d33391312`。Windows 和两个 macOS 二进制为本次构建；Linux x86_64 二进制来自[同一提交的原生 CI](https://github.com/coloz/stc-cli/actions/runs/34034156215)，要求 GLIBC 2.34+，并已在 Ubuntu 运行上述 23 项离线固件校验。

完整的每配置 HEX SHA-256、工具版本和 stc-cli 二进制摘要保存在 [v0.0.2 附件](https://github.com/coloz/arduino-stc51/releases/tag/v0.0.2) 的 `release-qualification.json`。源码命令为 `python scripts/qualify-release.py --help`。`release-manifest.json` 记录全部附件大小和哈希；`scripts/verify-release-assets.py` 用于本地与标签 CI 复验。

以上是构建和离线镜像检查；未连接实板，不构成硬件运行、外设或完整 Arduino C++ 库兼容性认证。
